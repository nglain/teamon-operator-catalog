# TeamON Operator: установка → вход → пульт

Редакция 2026-09-22. Выпуск 0.3.8: публичный загрузчик и подписанный закрытый пакет.

Официальный каталог: https://github.com/nglain/teamon-operator-catalog.git
Ветка: main. Минимальная версия Operator: 0.3.8.
Старый teamon-operator-plugins закрыт и для новой установки не используется.
Публикация не заменяет проверку входа и данных компании на этом компьютере.

## Правила

Прочитай весь файл заново. Запрос «Установи» разрешает установку одного
официального Operator, получение подписанного рабочего пакета после входа
и открытие пульта. Запрос диагностики сам по себе установки не разрешает.
Без отдельного Installer, Visualize, MCP Apps экрана установки, процентов,
таймеров, имитации и автоматической отправки сообщений. HTML-пульт нужен.

Сохраняй входы, ручные подключения, отключённые пакеты и настройки. Не заменяй
старый одноимённый каталог без согласования. Пароль вводится только в браузере
на https://master.nglain.com. PAT, GitHub-аккаунт и новые учётные записи не нужны.

## 1. Установить публичный загрузчик

После проверки опубликованного статуса скажи: «Установлю TeamON Operator,
помогу войти и открою рабочий пульт. Подтверждённые этапы покажу здесь».

```text
[>] Проверка среды
[ ] Плагин установлен
[ ] Инструменты подключены
[ ] Вход подтверждён
[ ] Рабочий пакет проверен и запущен
[ ] Пульт открыт
```

Проверь macOS/Linux, Node >=24.14.1 <25, Git и Codex CLI с plugin-командами.
Используй один проверенный CLI. Системные зависимости молча не устанавливай.
Проверь `codex plugin marketplace list --json` и
`codex plugin list --marketplace teamon-operator --available --json`.
--available обязателен для отсутствующего пакета.

Сверь источник https://github.com/nglain/teamon-operator-catalog.git, main и минимальную версию 0.3.8.
Сторонний источник, старый приватный каталог, закреплённый ref или отключённый
пакет требуют уточнения. Не заменяй их молча и не запрашивай PAT.
Целевая версия — не ниже минимума этой инструкции и версии, явно запрошенной
пользователем (сравнивай числовые major/minor/patch). Проверяй установку именно
на текущем компьютере: обновление на другом устройстве сюда не переносится.
Подходящий установленный и включённый пакет повторно не устанавливай.
Если официальный включённый пакет ниже целевой версии,
обнови только этот каталог через `codex plugin marketplace upgrade teamon-operator`,
затем один раз `codex plugin add teamon-operator@teamon-operator`.
Это обновление исправления, а не удаление/переустановка профиля: вход и настройки
сохраняются. Проверь новую версию; при старом наборе инструментов — раздел 2.
Для отсутствующего пакета добавь только закреплённый публичный каталог
штатной командой `codex plugin marketplace add https://github.com/nglain/teamon-operator-catalog.git`, затем один раз
`codex plugin add teamon-operator@teamon-operator`.
Повторным scoped list проверь version/enabled. При потере ответа сначала
проверь состояние; не повторяй add вслепую. Более новую версию не понижай.
Загрузчик установлен ≠ инструменты подключены ≠ рабочий пакет запущен.

## 2. Подключить инструменты

Свежим поиском проверь инструменты, включая отложенные; не используй список
из предыдущего хода. В code-mode:

```javascript
text(ALL_TOOLS.filter(t => /operator/i.test(t.name)).map(t => t.name));
```

Нужны installation_status, account_login_open, operator_setup,
operator_runtime_info и operator_workspace_open именно из TeamON Operator, не Probe.
Если доступны — проверь версию запущенного процесса через installation_status
или operator_runtime_info. Если она соответствует установленному обновлению и
не ниже целевой — продолжай сразу в этой задаче, без перезапуска.
Наличие всех 36 методов само по себе не доказывает, что запущена новая версия.
Если после обновления процесс старый или у установленного/enabled плагина
нет инструментов в текущей задаче, не проси перезапускать Codex. Следующий шаг:

> Открой новую задачу в Codex, выбери @TeamON Operator через нативное меню
> упоминаний и напиши «Продолжи установку Operator». Плагин уже установлен,
> повторная установка не нужна.

Перед переходом сообщи установленную версию и последний подтверждённый этап.
Для новой задачи дай самодостаточное продолжение (вместе с нативным упоминанием):

> Обнови или заверши установку TeamON Operator 0.3.8 по актуальной инструкции
> https://master.nglain.com/downloads/teamon-operator-install.md.
> На этом компьютере проверь установленную и запущенную версии. Если пакет
> старее 0.3.8, обнови его штатно один раз, сохранив вход и настройки. Более
> новую версию не понижай. Проверь реальные инструменты. Заверши вход и
> operator_setup, затем сам открой
> настоящий пульт во встроенном браузере Codex и проверь видимость агентов
> назначенной компании без чтения переписок и изменения данных.

После «Продолжи» проверь реальные инструменты и версию процесса, затем продолжай
с незавершённого этапа. Если в новой задаче после нативного @TeamON Operator
инструменты отсутствуют — раздел 5: диагностика конкретной ошибки. Не повторяй
упоминания, установки или переходы по кругу и не предлагай перезапуск Codex.
Если в новой задаче процесс всё ещё старее установленного пакета, не предлагай
ещё одну новую задачу по кругу: проверь точный источник и конфигурацию Operator,
зафиксируй установленную/запущенную версии и namespace инструментов. Старый
пульт не является успешным завершением запрошенного обновления.
Не создавай задачу и не отправляй сообщение автоматически без запроса человека.
Не переноси в текст продолжения токены, пароль или временный URL входа.

## 3. Вход и закрытый рабочий пакет

Вызови installation_status: сам status ничего не скачивает.
operator_runtime_required означает отсутствие активного рабочего пакета.
Для проверки сохранённого входа вызови status с refresh_account:true.
account_login_required означает необходимость входа, не переустановки.

Если вход нужен, вызови account_login_open один раз, открой возвращённый
официальный HTTPS URL во встроенном браузере Codex. Покажи только публичный userCode для сверки:
«Войди в TeamON и подтверди подключение на странице. Дожидаюсь подтверждения».
Не создавай новую попытку при pending; не используй localhost callback.

По явному запросу установки вызывай operator_setup({wait_seconds:45}).
При account_authorization_pending продолжай ограниченное ожидание: соблюдай
retryAfter, максимум пять минут суммарно и не дольше expiresAt. Между вызовами
сообщай фактическое состояние. «Готово» не требуй штатно: после подтверждения
setup получает пакет, проверяет подпись и запускает runtime.
Для запроса «только проверь версию» setup запрещён.

При отмене/истечении остановись, сохрани настройки, предложи новый вход.
Outage не выдавай за отказ в доступе. Не стирай сессию. Если пользователь
остановил ожидание, новый запрос «Продолжи» возобновит проверку; бесконечного
фонового ожидания нет. operator_download_timeout / operator_download_network_error означают проблему
получения частей пакета, а operator_release_busy — временную занятость сервера.
Загрузчик сам ограниченно повторяет неудачные части и сохраняет скачанное;
не запускай установки параллельно. `operator_download_paused` с `download`
означает сохранённый прогресс, а не потерю входа. При росте downloadedBytes
один раз продолжи `operator_setup({wait_seconds:45})` в этой же задаче:
он докачает недостающие части. Допускаются не более двух окон загрузки по
5 минут (10 минут всего). Без продвижения или после общего предела назови
точный reason и сохранённый объём; следующий явный «Продолжи» возобновит
докачку. Не предлагай переустановку или перезапуск из-за сетевого тайм-аута.
Ошибка подписи/целостности блокирует запуск: нельзя
отключать проверку или вручную скачивать другой URL.

state:installed подтверждает запуск рабочего пакета, но ещё не открытый пульт.
Проверь installation_status с refresh_account:true. Готовый пакет повторно
не скачивается. Устаревшая полная поставка без operator_setup требует отдельной
миграции, а не обхода загрузчика.

## 4. Пульт и компания — в UI, не в чате

После setup сверь operator_runtime_info с целевой версией; имя сервера
teamon-operator-bootstrap ещё не доказывает запуск рабочего пакета.
После подтверждения входа и нужной версии сам вызови operator_workspace_open и открой именно
возвращённый URL во **встроенном браузере Codex (in-app browser)**, видимо для
пользователя. Не жди дополнительного «открой админку». Не используй Chrome,
Safari или системный браузер для этого шага. Не подменяй пульт Master admin,
старой вкладкой, connected-статусом или демонстрационным HTML.

После открытия прочитай состояние страницы: дождись настоящего пульта,
проверь версию в шапке, выбранную компанию и видимость агентов, не открывая переписки. Оставь
вкладку пульта открытой для пользователя. Вызов workspace_open, возвращённый
URL, queued или запуск runtime сами по себе не подтверждают открытие страницы.
Не заканчивай сообщением «Operator установлен и запущен», пока пульт не открыт
во встроенном браузере и результат не проверен. Если браузер недоступен или
страница не загрузилась, явно укажи незавершённый этап и ссылку; не заявляй,
что установка до пульта завершена.

- Одна назначенная компания — пульт подключает и открывает её автоматически.
- Несколько — человек нажимает карточку, отдельный запрос в чат не нужен.
- Ноль — пульт показывает отсутствие назначений; доступ выдаёт администратор
  в https://master.nglain.com/admin/operators. Установщик права не меняет.
- Старое согласие — кнопка входа в пульте открывает обновлённое браузерное
  подтверждение, без переустановки и молчаливого расширения прав.
- Отозванный доступ/ошибка компании — явная ошибка, не пустой «успешный» экран.

Короткий гайд: «Выбери агента и обращение в пульте. Для анализа или изменений
напиши задачу здесь. Действия с данными и отправку сообщений подтверждаем
отдельно». Пульт выполняет навигацию и подключение, не бизнес-записи.
Пульт открыт ≠ данные компании проверены: отдельно укажи, видны ли агенты/
обращения. Не делай отправок и изменений ради проверки.

При `operator_installing` продолжай вызывать `operator_setup({wait_seconds:45})`:
это ожидание той же загрузки, не новая установка. Один вызов ждёт не более
45 секунд; предел одного окна загрузки — 5 минут, с одним продолжением
сохранённого прогресса по правилу выше. Все задачи Codex на одном
компьютере используют общий локальный координатор: только одна из них скачивает
подписанный пакет, остальные ждут тот же результат. Не запускай второй setup
параллельно, не переустанавливай плагин и не перезапускай Codex из-за этого
состояния. После освобождения старого процесса повторный явный вызов продолжит
с того же состояния; уже сохранённый пакет повторно не скачивается.

## Личная адаптация рабочего пульта

Пульт — локальный рабочий интерфейс. По запросу пользователя исправляй подписи,
компоновку и представление данных; не отвечай автоматически «только в следующем
релизе». Возможности Operator шире кнопок пульта: сначала проверь доступные MCP
инструменты и данные для выбранной компании, агента и пользователя.

Если схема `operator_workspace_open` поддерживает `appearance`, вызови
`operator_workspace_open({appearance:"personal"})`. Он создаёт личную HTML-копию
и возвращает `ui.path`. Прочитай и измени этот файл обычными файловыми средствами
хоста, обнови возвращённый URL во встроенном браузере и проверь результат.
Повторный вызов сохраняет существующие правки; `appearance:"standard"` открывает
стандартный интерфейс в текущем процессе, не удаляя личный файл. Личная копия
сохраняется при обновлении пакета; `ui.based_on_version` — её исходная версия,
а номер в шапке — версия запущенного runtime. После обновления проверь совместимость.

Используй существующий локальный мост чтения. Например, имена возьми из
`agent_inspect` и сопоставь по точным agent/user ID; семантические интенты определи
LLM текущей сессии через доступные intent tools. Другие разрешённые задачи делай
через MCP в чате, даже если для них нет кнопки. Сохрани выбор области,
ссылки на источники, реальные статусы и номер runtime. Не расширяй браузерный
доступ до бизнес-записей и секретов. Не заменяй MCP прямыми shell-запросами.

Не редактируй подписанный runtime и служебный кеш плагина. Если установленная
версия ещё не поддерживает личную копию, прямо назови эту отсутствующую
возможность: анализ и доступные MCP-действия можно выполнить уже сейчас, а
адаптацию пульта продолжить после обновления. Личная правка не является выпуском
для всех пользователей; кнопка не запускает сессию автоматически без реально
подключённого канала передачи запроса.

## 5. Диагностика без переустановок по кругу

Различай установленный пакет, MCP-процесс, каталог этой задачи, вход,
подписанный runtime, открытый экран и доступ к компании.

Эти названия — категории диагностики, не доказательство причины сами по себе.
В отчёте обязательно укажи конкретный отсутствующий метод, версию и источник
пакета, имена/число raw tools/list и инструментов текущей задачи. Если сырой
каталог не проверен, не называй состояние server_missing или host_inventory_mismatch.
Ошибка загрузчика `unknown field tool_timeout_sec` относится к дефектной поставке
0.2.20: обнови до 0.3.8 или новее штатным путём выше. Перезапуск без обновления
этот дефект не исправляет; не добавляй поле обратно в mcp.json.

- unverified — фактов недостаточно, причина не подтверждена.
- startup_error — подтверждённая ошибка запуска, безопасный текст ошибки.
- server_missing — метода нет в сыром tools/list проверенного пакета.
- host_inventory_mismatch — метод есть у проверенного сервера, но отсутствует
  в свежем поиске текущей задачи. installed/enabled этого не доказывает.

Если в новой задаче после нативного упоминания инструменты отсутствуют, собери
read-only version/sourceCommit/processInstanceId/toolCount, если диагностический
метод доступен, и имена ALL_TOOLS. package.json не подтверждает версию процесса.
Проверь безопасные ошибки запуска и разрешённый путь через `codex mcp get
teamon-operator-runtime`. Буквальный `${PLUGIN_ROOT}` в пути — ошибка конфигурации
запуска, а не проблема входа. Сверь portable plugin.json/mcp.json поставки.
Не добавляй alias, shell-вызов действия или второй MCP.
Не вызывай бизнес-методы через терминал. Назови блокер и остановись.

## Завершение

Подтверждены плагин, инструменты, вход, проверенный runtime и открытый пульт.
Доступность компании укажи отдельно. Не объявляй «всё готово», если шаг остался
непроверенным; назови один следующий шаг.
