# TeamON Operator: установка → вход → пульт

Редакция 2026-09-21. Выпуск 0.2.19: публичный загрузчик и подписанный закрытый пакет.

Официальный каталог: https://github.com/nglain/teamon-operator-catalog.git
Ветка: main. Минимальная версия Operator: 0.2.19.
Старый teamon-operator-plugins закрыт и для новой установки не используется.
Публикация не заменяет проверку входа и данных компании на этом компьютере.

## Правила

Прочитай весь файл заново. Запрос «Установи» разрешает установку одного
официального Operator, получение подписанного рабочего пакета после входа
и открытие пульта. Запрос диагностики сам по себе установки не разрешает.
Без отдельного Installer, Visualize, MCP Apps экрана установки, процентов,
таймеров, имитации и автоматической отправки сообщений. HTML-пульт нужен.

Сохраняй входы, ручные подключения, отключённые пакеты и настройки. Не заменяй
старый одноимённый каталог без согласования. Пароль вводится только в браузере
на https://master.nglain.com. PAT, GitHub-аккаунт и новые учётные записи не нужны.

## 1. Установить публичный загрузчик

После проверки опубликованного статуса скажи: «Установлю TeamON Operator,
помогу войти и открою рабочий пульт. Подтверждённые этапы покажу здесь».

```text
[>] Проверка среды
[ ] Плагин установлен
[ ] Инструменты подключены
[ ] Вход подтверждён
[ ] Рабочий пакет проверен и запущен
[ ] Пульт открыт
```

Проверь macOS/Linux, Node >=24.14.1 <25, Git и Codex CLI с plugin-командами.
Используй один проверенный CLI. Системные зависимости молча не устанавливай.
Проверь `codex plugin marketplace list --json` и
`codex plugin list --marketplace teamon-operator --available --json`.
--available обязателен для отсутствующего пакета.

Сверь источник https://github.com/nglain/teamon-operator-catalog.git, main и минимальную версию 0.2.19.
Сторонний источник, старый приватный каталог, закреплённый ref или отключённый
пакет требуют уточнения. Не заменяй их молча и не запрашивай PAT.
Подходящий установленный и включённый пакет повторно не устанавливай.
Для отсутствующего пакета добавь только закреплённый публичный каталог
штатной командой `codex plugin marketplace add https://github.com/nglain/teamon-operator-catalog.git`, затем один раз
`codex plugin add teamon-operator@teamon-operator`.
Повторным scoped list проверь version/enabled. При потере ответа сначала
проверь состояние; не повторяй add вслепую. Более новую версию не понижай.
Загрузчик установлен ≠ инструменты подключены ≠ рабочий пакет запущен.

## 2. Подключить инструменты

Свежим поиском проверь инструменты, включая отложенные; не используй список
из предыдущего хода. В code-mode:

```javascript
text(ALL_TOOLS.filter(t => /operator/i.test(t.name)).map(t => t.name));
```

Нужны installation_status, account_login_open, operator_setup,
operator_workspace_open именно из TeamON Operator, не Probe.
Если доступны — продолжай сразу. Иначе предложи создать новую задачу,
выбрать @TeamON Operator из меню упоминаний и отправить:

> Заверши установку TeamON Operator: проверь installation_status.
> Если нужен вход — открой account_login_open и дожидайся подтверждения через
> operator_setup с wait_seconds:45, не более пяти минут. Получи и проверь рабочий
> пакет через operator_setup, затем проверь вход и открой пульт через
> operator_workspace_open. Этапы показывай текстом. Плагин не переустанавливай.
> Пароли в чате не запрашивай, сообщения не отправляй сам.

Новый запрос не зависит от файла или истории предыдущей задачи.
Настоящее упоминание — выбор плагина в меню, не просто текст с @.
Не создавай задачу и не отправляй сообщение автоматически.
Полный перезапуск приложения
не является обязательным шагом. При повторном отсутствии — раздел 5.

## 3. Вход и закрытый рабочий пакет

Вызови installation_status: сам status ничего не скачивает.
operator_runtime_required означает отсутствие активного рабочего пакета.
Для проверки сохранённого входа вызови status с refresh_account:true.
account_login_required означает необходимость входа, не переустановки.

Если вход нужен, вызови account_login_open один раз, открой возвращённый
официальный HTTPS URL в браузере. Покажи только публичный userCode для сверки:
«Войди в TeamON и подтверди подключение на странице. Дожидаюсь подтверждения».
Не создавай новую попытку при pending; не используй localhost callback.

По явному запросу установки вызывай operator_setup({wait_seconds:45}).
При account_authorization_pending продолжай ограниченное ожидание: соблюдай
retryAfter, максимум пять минут суммарно и не дольше expiresAt. Между вызовами
сообщай фактическое состояние. «Готово» не требуй штатно: после подтверждения
setup получает пакет, проверяет подпись и запускает runtime.
Для запроса «только проверь версию» setup запрещён.

При отмене/истечении остановись, сохрани настройки, предложи новый вход.
Outage не выдавай за отказ в доступе. Не стирай сессию. Если пользователь
остановил ожидание, новый запрос «Продолжи» возобновит проверку; бесконечного
фонового ожидания нет. Ошибка подписи/целостности блокирует запуск: нельзя
отключать проверку или вручную скачивать другой URL.

state:installed подтверждает запуск рабочего пакета, но ещё не открытый пульт.
Проверь installation_status с refresh_account:true. Готовый пакет повторно
не скачивается. Устаревшая полная поставка без operator_setup требует отдельной
миграции, а не обхода загрузчика.

## 4. Пульт и компания — в UI, не в чате

После подтверждения входа вызови operator_workspace_open и открой возвращённый
URL штатным браузерным инструментом. Не подменяй его Master admin, connected,
старой вкладкой или демонстрационным HTML. queued не означает «открыт».
Если открыть автоматически невозможно, дай ссылку с честным статусом.

- Одна назначенная компания — пульт подключает и открывает её автоматически.
- Несколько — человек нажимает карточку, отдельный запрос в чат не нужен.
- Ноль — пульт показывает отсутствие назначений; доступ выдаёт администратор
  в https://master.nglain.com/admin/operators. Установщик права не меняет.
- Старое согласие — кнопка входа в пульте открывает обновлённое браузерное
  подтверждение, без переустановки и молчаливого расширения прав.
- Отозванный доступ/ошибка компании — явная ошибка, не пустой «успешный» экран.

Короткий гайд: «Выбери агента и обращение в пульте. Для анализа или изменений
напиши задачу здесь. Действия с данными и отправку сообщений подтверждаем
отдельно». Пульт выполняет навигацию и подключение, не бизнес-записи.
Пульт открыт ≠ данные компании проверены: отдельно укажи, видны ли агенты/
обращения. Не делай отправок и изменений ради проверки.

## 5. Диагностика без переустановок по кругу

Различай установленный пакет, MCP-процесс, каталог этой задачи, вход,
подписанный runtime, открытый экран и доступ к компании.

- unverified — фактов недостаточно, причина не подтверждена.
- startup_error — подтверждённая ошибка запуска, безопасный текст ошибки.
- server_missing — метода нет в сыром tools/list проверенного пакета.
- host_inventory_mismatch — метод есть у проверенного сервера, но отсутствует
  в свежем поиске текущей задачи. installed/enabled этого не доказывает.

После настоящего упоминания в новой задаче при отсутствии инструментов собери
read-only version/sourceCommit/processInstanceId/toolCount, если диагностический
метод доступен, и имена ALL_TOOLS. package.json не подтверждает версию процесса.
Не добавляй alias, shell-вызов действия или второй MCP.
Не вызывай бизнес-методы через терминал. Назови блокер и остановись.

## Завершение

Подтверждены плагин, инструменты, вход, проверенный runtime и открытый пульт.
Доступность компании укажи отдельно. Не объявляй «всё готово», если шаг остался
непроверенным; назови один следующий шаг.
